# Silent Bug Hunt Checklist

Report **FOUND** / **NOT FOUND** with file and line evidence for each.

---

## General ML Anti-Patterns

### 1. Off-by-one in Sequence Modeling
Padding tokens included in loss computation, inflating accuracy with trivially correct predictions on pad positions.
- Check: Is the loss masked for padding indices?
- Check: Does the attention mask correctly exclude padding?

### 2. sklearn Pipeline Fit on Full Dataset Before Split
`fit_transform()` called on the entire dataset, then split into train/test — test set statistics leak into training.
- Check: Trace the order of `fit_transform()` and `train_test_split()`.
- Check: Is `Pipeline` created before or after the split?

### 3. DataFrame Index Leakage
Sorting by index reveals label ordering, allowing the model to exploit row position as a proxy for the label.
- Check: Is the index reset/shuffled before splitting?
- Check: Is row index used as a feature?

### 4. Train Metrics Labeled as Test
Metrics computed on the training set but presented as "test" or "validation" results.
- Check: Trace the data variable passed to the evaluation function — is it `X_test` or `X_train`?
- Check: Are variable names misleading (e.g., `test_data` that actually holds training data)?

### 5. Missing Class Weights in Loss
Paper claims class-weighted loss, but the code uses default (uniform) weights.
- Check: Is `class_weight`, `pos_weight`, or `weight` actually passed to the loss function?
- Check: If weights are defined, are they used or just assigned to an unused variable?

### 6. Double Softmax
Softmax applied in the model's forward pass AND again in the loss function (e.g., using `nn.CrossEntropyLoss` which expects raw logits, not probabilities).
- Check: Does the model end with `softmax()` or `log_softmax()`?
- Check: Does the loss function expect logits or probabilities?

### 7. Data Augmentation on Validation/Test Set
Augmentation transforms (random crop, flip, noise) applied to val/test data, making evaluation non-deterministic and potentially inflating metrics.
- Check: Are separate transforms defined for train vs val/test?
- Check: Is the same `DataLoader` used for training and evaluation?

### 8. LR Scheduler Step at Wrong Frequency
`scheduler.step()` called per batch when it should be per epoch (or vice versa), causing the learning rate to decay too fast or too slow.
- Check: Where is `scheduler.step()` called relative to the training loop structure?
- Check: For `ReduceLROnPlateau`: is the monitored metric actually passed to `step()`?

### 9. Gradient Accumulation Without Scaling
When using gradient accumulation over N steps, the loss is not divided by N, effectively multiplying the learning rate.
- Check: Is `loss = loss / accumulation_steps` applied before `backward()`?

### 10. BatchNorm in Eval Mode During Training (or Vice Versa)
`model.eval()` called during training (freezing BN stats), or `model.train()` not called during training.
- Check: Is `model.train()` / `model.eval()` toggled correctly around training and evaluation?

### 11. Detached Gradients in Custom Loss
`.detach()` or `.item()` called on tensors that should propagate gradients, silently breaking backpropagation.
- Check: Are intermediate tensors in custom losses accidentally detached?
- Check: Does the loss value actually require gradients? (`loss.requires_grad` should be True)

## Agentic AI / LLM-Based System Anti-Patterns

### 12. Pre-Scripted Agent Trajectories
The agent loop doesn't actually execute LLM calls — actions are read from a script or hardcoded sequence.
- Check: Are LLM API calls actually made, or are responses read from a file?
- Check: Does the agent's action selection depend on the observation, or is it a fixed sequence?
- Check: Are there suspiciously deterministic trajectories across different scenarios?

### 13. Mock Tool Calls
Tool-use functions return hardcoded values instead of actually executing.
- Check: Do tool functions perform real operations (API calls, computations, DB queries)?
- Check: Are there `return {"status": "success", "result": ...}` stubs?
- Check: Is there a `mock` or `fake` module that intercepts tool calls?

### 14. Prompt/Response Fabrication
Claimed LLM interactions that were manually written, not actually generated.
- Check: Are logged conversations actually generated by the claimed model?
- Check: Do response logs contain suspiciously consistent formatting that no LLM would produce?
- Check: Are there example outputs that exceed the claimed model's capabilities?

### 15. Evaluation on Seen Examples
The agent is evaluated on the same scenarios it was demonstrated on or fine-tuned with.
- Check: Is there overlap between demonstration/few-shot examples and test cases?
- Check: Are evaluation scenarios genuinely novel, or variations of training examples?

## Reinforcement Learning Anti-Patterns

### 16. Reward Hacking Not Addressed
The agent finds a shortcut in the reward function that inflates returns without solving the task.
- Check: Is the reward function robust to trivial exploits?
- Check: Are reward curves correlated with actual task performance (not just reward maximization)?
- Check: Are qualitative rollout visualizations provided alongside quantitative metrics?

### 17. Environment Interaction Faked
The RL agent doesn't actually interact with the environment — trajectories are pre-generated.
- Check: Does `env.step()` actually execute, or is the environment mocked?
- Check: Are state transitions physically/logically consistent?
- Check: Is the environment deterministic in a way that makes "learning" trivial?

### 18. Single-Environment Overfitting
Results reported on a single environment configuration, hiding that the agent fails on variations.
- Check: Is the agent evaluated across multiple environment seeds/configurations?
- Check: Are initial conditions varied during evaluation?

---

## Federated Learning Anti-Patterns

### 19. All Clients Identical
Federated setup claims heterogeneous clients, but all clients have identical data and models.
- Check: Is data actually partitioned non-IID, or do all clients see the same distribution?
- Check: Do client models differ, or is it the same model trained N times on the same data?

### 20. Aggregation Not Applied
`FedAvg` or other aggregation claimed, but global model is just the last client's model.
- Check: Is the aggregation function actually called and its output used?
- Check: Does the global model's state dict change after aggregation in a way consistent with averaging?

### 21. Privacy Claims Without Mechanism
Paper claims differential privacy or secure aggregation, but no privacy mechanism exists in code.
- Check: Is noise actually added for DP? With what epsilon?
- Check: Is secure aggregation implemented, or just mentioned?
- Check: Is the privacy budget tracked and enforced?

---

## Digital Twin / Simulation Anti-Patterns

### 22. Simulation Results Passed as Real
Synthetic simulation outputs presented as real-world validation.
- Check: Are results from sim clearly labeled as simulation, or presented ambiguously?
- Check: Is there a sim-to-real gap analysis?

### 23. Unrealistic Simulation Parameters
Simulation uses parameters that produce trivially good results (e.g., no noise, perfect observations, instant actions).
- Check: Are noise models and delay models realistic?
- Check: Are environment dynamics calibrated against real-world data?
